【v1.2.1】2026-09-19
------------------------------------------------------------
■ 形态升级：无黑窗桌面 App（本次重点之一）
1. 双击后直接打开独立的"清源QMS"桌面窗口，不再出现黑色控制台：
   启动过程在窗口内分段显示进度（首次 30~60 秒，之后 10~25 秒），
   启动完成自动进入登录页，全程不再依赖外部浏览器。
2. 首次成功启动后自动创建桌面与开始菜单快捷方式，之后双击桌面
   图标即可使用；无托盘图标、无开机自启。
3. 关窗即完全退出：关闭窗口会按"后端 → Redis 存盘 →
   MariaDB 干净关闭"的顺序停止全部内置服务并释放端口，
   后台不留任何残留进程。
4. 窗口右下角内置"清源工具"：刷新页面、重启服务、
   打开日志目录、打开数据目录、关于本系统。
5. 窗口基于系统自带的 WebView2 运行时（Win10/11 多数已预装）；
   极少数未预装的电脑会弹出中文引导，按提示安装后即可使用。

■ 闲置假死根治（本次重点之二）
6. 守护探针从"只看健康端点"升级为真实业务探针：
   新增本机诊断端点 /api/v1/diag/ping，用独立数据库连接
   执行 SELECT 1 并对缓存执行 PING（3 秒超时），
   能识别"服务进程活着、health 偶尔还报 UP，但业务请求
   已全部卡死"（线程池/连接池耗尽）这一旧版盲区。
7. 看门狗每 10 秒巡检一次，连续 3 次业务探针失败
   （约 30~45 秒）即判定假死：先把现场固化到
   logs\freeze-时间戳\（探针时间线、JVM 线程栈、
   health 明细、后端日志尾部），再自动重启后端，
   恢复后 App 窗口自动刷新页面，无需人工介入；
   自动重启设有每小时次数上限，异常时会明确提示。
8. 进程树由 Windows Job Object 统一托管，无论正常关窗、
   注销关机还是异常退出，内置 Java/MariaDB/Redis 都不会
   在后台残留。

■ 质量改进
9. 前端 11 个页面共 20 处受控弹窗统一为预渲染模式，
   开发态 useForm 懒挂载告警清零（不影响功能，属控制台噪音治理）。
10. 后端 76 项自动化测试全部通过；冷冒烟覆盖
    "无黑窗 / 关窗清理 / 模拟假死自动恢复"三类场景。

■ 升级说明（从 v1.2.0 及更早版本替换）
1. 保留 data 目录，替换 app 目录与 清源QMS.exe 即可，历史数据不受影响；
2. 使用习惯变化：以前是"关黑窗退出"，现在是"关 App 窗口退出"，
   不要再去任务栏找控制台窗口；
3. 本版本不改动数据库表结构，无需任何人工迁移。

【v1.2.0】2026-09-18
------------------------------------------------------------
■ 新增功能：以商品（SKU）为中心的全流程品控台账
  在原有检验任务、质检报告、不合格闭环、供应商整改、批次效期、
  质量预警、新品引入（NPI）、主数据等全部功能之上新增，
  原有功能与数据不受影响。

1. 商品台账：
   - 商品基础信息：SKU、产品通用名、规格、生产企业、批准文号/备案号、
     UPC(69码)、品牌、一级/二级品类、过会时间；
   - 流程总览：最终合作结论（合作/待定/不合作）、上市日期、当前流程节点；
   - 列表支持 SKU/名称/品牌/生产企业关键字搜索，按品类/结论/当前节点筛选、
     分页；商品增删改查，删除需二次确认。
2. 全流程记录（商品详情内）：
   - 一条可视化流程线贯穿：过会 → 供应商准入审核 → 实地验厂 →
     包装审核确认 → 上市 → 上市后质量监控（默认示例模板，非写死）；
   - 每个节点可记录状态（未开始/进行中/已完成/不通过）、完成日期、
     负责人、结论、附件、备注；准入审核/实地验厂节点可关联现有供应商；
   - 横向步骤条直观展示：已完成高亮、当前节点标识、未开始置灰。
3. 流程模板配置（仅管理员）：
   - 可新建/编辑模板，节点可增删改、拖拽排序；
   - 每个节点可自定义字段：文本/多行文本/日期/下拉选项/附件/结论，
     下拉选项可自定义；
   - 系统预置一套默认六环节示例模板，可整体复制后修改，不强制使用；
   - 商品关联模板版本，模板后续改动不强制追溯历史商品（详情内有提示）。
4. Excel 批量导入（仅管理员）：
   - 标准模板下载，含"填写说明"工作表；
   - 按 SKU 匹配：不存在则新建、已存在可选择"更新已有/跳过已有"；
   - 供应商按名称匹配，不存在时自动新建为合格供应商；
   - 导入结果逐行反馈：成功（新建/更新/跳过）、失败逐行列出中文原因；
   - 流式分批解析，大文件不卡死。
5. 品控工作台（商品品控台账 → 品控工作台）：
   - 四张统计卡片：商品总数、供应商总数、全流程记录数、资料重点缺口数；
   - 三张分布图（ECharts）：过会状态分布、当前流程节点分布、一级品类分布；
   - 资料重点缺口明细列表，点击商品行可直接进入详情补齐资料。
6. 资料清单与重点缺口识别：
   - 每个商品挂资料清单（产前样品、标准样品、型式检验报告、
     批准文号、包装确认稿、供应商资质文件、实地验厂报告、
     第三方外检报告等预置示例项，管理员可维护资料项）；
   - 每项资料状态：齐套/缺失/待确认，可上传附件佐证；
   - 工作台与商品详情自动统计"缺失/待确认"为重点缺口。
7. 质量报表导出（Excel）：
   - 商品台账（含流程总览）、全流程记录（商品×节点）、
     资料缺口清单三类报表；
   - 报表含"导出说明"工作表，标注导出时间与所用筛选条件。

■ 脱敏演示数据与一键清除
8. 系统预置 36 个全虚构演示商品（覆盖已上市/在途各节点/待定/不合作
   等状态）、8 家虚构供应商及配套流程记录与资料缺口；
   品牌、厂家、商品名全部为"示例健康/演示制药/虚构堂"等编造信息，
   不含任何真实商家、商品或人员信息。
9. "商品品控台账 → 演示数据管理"页可一键清除全部演示数据：
   - 红色警示 + 必须手动输入"清除"二次确认；
   - 仅删除数据来源标记为"演示(DEMO)"的数据；
   - 账号、品类主数据、流程模板、资料项定义、系统配置以及用户自行
     录入或导入的数据（USER）全部保留，清除后系统功能正常。

■ 技术说明（运维/升级）
10. 新增数据库迁移 V14（台账 8 张表 + 权限/预置模板/预置资料项）、
    V15（虚构演示数据）、V16（品控工作台菜单权限），
    启动时自动执行，不改动 V1~V13 的任何历史对象；

    一键清除只删除 DEMO。
12. 沿用既有单机离线架构与连接/事务规范，原有检验、不合格闭环、

13. 前端控制台告警清理：权限按钮补全 ref 转发（消除 Popconfirm/Tooltip

    这些均为开发态控制台告警，不影响任何操作与数据。

【v1.1.0】2026-09-17
------------------------------------------------------------
■ 新增功能
1. 品类可以"随手建"了：
   在 NPI 新品会立项、产品档案、检验模板里选择品类时，
   下拉框最下面多了一个"＋ 新建品类"按钮。
   遇到系统里还没有的新品类，不用再专门跑到
   "主数据 → 品类"页面，直接在当前弹窗里填
   编码、名称、上级品类、排序，点"保存并选中"即可——
   保存成功后品类树自动刷新、新类目自动填好，不用刷新页面。
   编码重复等错误会直接红字提示在创建框里，改完可直接重试。
   （"主数据 → 品类"管理页的原有功能不变。）

■ 问题修复
1. 修复"放一段时间没用，回来整站打不开、提示网络问题"：
   这是本次最重要的修复。以前电脑闲置一段时间
   （尤其在每个整点前后），再操作系统可能所有页面都转圈、
   提示"网络出现问题"，黑窗也没有任何新日志，只能重启。
   本次对数据库连接、缓存连接全部加了超时、保活和
   连接泄漏检测；缓存服务异常时系统自动降级运行，
   不再因为一个后台服务抖动把整个系统拖死。
2. 后台整点预警扫描、每天 8:30 的定时任务增加了完整的
   异常兜底：单次扫描出问题只记日志，不再影响后续执行
   和正常业务操作。
3. 启动器（清源QMS.exe）新增"守护 + 自愈"：
   - 内置数据库 / 缓存 / 后端任何一个异常退出，会自动拉起；
   - 后端进程活着但长时间不响应时，健康检查连续失败会自动重启；
   - 运行中服务意外停止，一般 1 分钟内自动恢复，刷新页面即可。
4. 启动失败时不再"黑窗卡住没反应"：
   会弹窗并在黑窗打印明确的中文原因，区分
   "端口被占用（18080/13306/16379）""数据库启动失败"
   "后端启动失败（密码/配置问题）"三类，方便排查。
5. 关闭黑窗改为"优雅关停"：先保存数据、正常关闭数据库，
   避免下次启动时数据库做崩溃恢复（表现为启动变慢）。
6. 数据库参数优化：连接数、锁等待超时、空闲断开时间等
   按单机场景调整，减少长时间运行后的连接异常。
7. 修复一个首次启动缺陷：解压到含中文或层级较多的文件夹时，
   首次初始化数据库可能卡住，黑窗提示"数据库初始化实例启动超时"。
   根因是数据库配置文件里 Windows 路径的反斜杠会被当作转义符
   （如 \r、\s 会破坏路径），且该文件必须使用 UTF-8 编码；
   现已统一改为正斜杠路径并以 UTF-8 写入，解压到任意
   中文/英文文件夹均可正常初始化启动。
8. 修复解压到桌面（C:\Users 用户名 等目录）时启动器一直等待、
   最终提示"后端启动失败/未就绪"的问题：
   系统自检会读取缓存服务的运行信息，其中带有程序所在路径，
   而路径里的"反斜杠+字母 u"（如 Users）会被 Java 的配置解析器
   误认为 Unicode 转义符，导致自检里缓存分项一直失败、
   整体健康状态不是 UP，启动器据此误判启动失败（实际服务已启动，
   黑窗日志持续刷 Redis health check failed）。
   现已把缓存自检改为最简单可靠的 PING 探活，不再解析运行信息，
   解压到任意路径（含桌面、中文、长路径）均判定正常。

■ 安全加固
9. 内置演示账号密码整体轮换（重要）：
   原来的弱口令 admin / admin123（以及其他角色的
   Qms@12345）已全部失效，5 个演示账号统一改为：
       账号：admin（及 sampler / inspector / reviewer / qamanager）
       密码：Qms@Demo2026
   登录页与使用说明同步更新，并提示首次登录后尽快修改密码。
   注意：如果你以前自己改过某个账号的密码，该账号不受影响，
   仍使用你自己设置的密码。
10. JWT 登录令牌密钥改为从环境变量 QMS_JWT_SECRET 读取：
   对外部署时不配置密钥会直接拒绝启动；单机版只在本机
   127.0.0.1 运行，不受影响、无需任何操作。

■ 升级说明（从旧版替换）
1. 旧数据可以保留：只替换 app 目录和 清源QMS.exe，
   保留自己的 data 目录即可，历史数据不受影响。
2. 想体验全新演示数据：关闭程序后删除 data 目录再启动。
3. 本次新增数据库迁移 V13（仅轮换仍是初始密码的演示账号，
   不改动业务表结构），启动时自动执行、无需人工处理。
4. 升级保留 data 目录时，若你一直用初始密码登录，
   升级后请改用新演示密码 Qms@Demo2026 登录。
